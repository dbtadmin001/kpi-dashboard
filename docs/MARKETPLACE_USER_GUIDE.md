# Using the data marketplace

For anyone in the organisation who needs figures: business users, analysts and
data scientists. No prior knowledge of the warehouse is assumed.

---

## What you get

Five **certified data products**. These are the approved figures — if a number
appears on a slide, it should come from here.

| Product | What it tells you | Who can see it |
|---|---|---|
| **Application Throughput** | What arrived, what was completed, what is still open or overdue | Everyone |
| **Turnaround Performance** | How long work takes, and how much of that is waiting versus working | Everyone |
| **Delay Analysis** | Which workflow stage loses the most time | Everyone |
| **Indicator Performance** | Every KPI against its agreed target | Everyone |
| **Quality Metrics** | Compliance outcomes from inspections | Analysts and above |

You will not see `fact_ma_applications`, `nda_gold` or anything with `fact_` or
`dim_` in the name. That is deliberate — those are the plumbing. If you go
looking for them you will get "Access Denied: Cannot show tables of schema
iceberg.nda_gold" - they are refused, not merely absent from a menu.

## Finding what you need

Search OpenMetadata at **http://localhost:8585** in your own words. It is written
to answer questions, not schema names — all of these work:

- *how long do applications take*
- *backlog*
- *where are the delays*
- *which inspections were on time*
- *are we meeting our targets*

Each product page shows what the rows mean, the questions it answers, who owns
it, and where the data came from.

## What decides what you can see

Your **team**, not you personally. Every account belongs to a group in the
organisation's directory — `ma-analysts`, `data-science`, `executive` and so on —
and the group carries the access. Nobody is granted a table by name.

Two things follow from that. Access arrives the moment you are put in the group,
with no request to raise for each dataset. And when you change teams, what you can
see changes with you, in the dashboard and in SQL at the same time, because both
read the same group.

If you think you are in the wrong group, that is the thing to ask about — there is
no separate warehouse permission to chase.

## Signing in

**You have one password: your Keycloak account.** There is no separate warehouse
password and Trino holds no password list of its own — it asks Keycloak, every
time.

| You are | Your password is |
|---|---|
| A seed/demo account (`alice.nakato`, `dana.okello`, …) | Generated by Terraform. Ask an administrator, or read `docs/ACCESS.md` if you have it |
| A real joiner | Whatever the administrator set when they created you. It is temporary — Keycloak makes you change it at first sign-in |
| Unsure | `http://localhost:8180` → realm `nda`. If you can sign in there, that is the password |

You type it into Keycloak's sign-in page in your browser, and nowhere else. SQL
tools redirect you there and receive a token back; they never see the password.

Scripts and scheduled jobs cannot open a browser, so they exchange a password for
a token directly — that is for service accounts, not for people:

```bash
eval "$(python -m marketplace.auth env marketplace_owner)"   # dbt, notebooks, CI
```

## Connecting your tool

**Host** `127.0.0.1` **Port** `8443` **Catalog** `iceberg` **Schema** `marketplace`

Use `127.0.0.1`, not `localhost`: `localhost` resolves to the IPv6 address first
and some clients will not fall back.

### DBeaver

You sign in through the browser with your own account. The connection settings
are **the same for every person** — nothing is issued to you individually.

**Once per machine**, trust the platform CA:

```bash
python -m marketplace.tls trust --apply
```

On a managed machine this is already done — Ansible installs it (`--tags ca_trust`).

**Then the connection, identical for everyone:**

1. New Connection → **Trino**
2. Host `127.0.0.1`, Port `8443`, Database `iceberg/marketplace`
3. Username and Password: **empty**
4. Driver properties:

   | Property | Value |
   |---|---|
   | `SSL` | `true` |
   | `SSLUseSystemTrustStore` | `true` |
   | `externalAuthentication` | `true` |

5. Connect. A browser opens; sign in to Keycloak as yourself.

Leave `externalAuthenticationTokenCache` unset. Its default is `NONE`, which is
what you want: `MEMORY` caches the token for the whole DBeaver session, so a
second connection reuses the first person's identity.

No token to paste, nothing to re-run tomorrow, and an administrator does not
have to do anything when you join — being in the right Keycloak group is the
whole of it.

#### Troubleshooting

| Error | Cause |
|---|---|
| `No host specified: jdbc:trino://localhost127.0.0.1:8443/...` | The Host box holds two values. Clear it, leave only `127.0.0.1` |
| `TLS/SSL is required for authentication with username and password` | Something is in the **Password** box. Clear it. `SSL` not set to `true` gives the same message |
| `Authentication failed: Unauthorized` with a password set | Username+password can never work here — this cluster runs OAuth2 and JWT only, with no password authenticator |
| `PKIX path building failed` | The CA is not in the machine trust store. Run `python -m marketplace.tls trust --apply` |
| `Access Denied: Cannot access catalog iceberg` | Signed in, but your account is in no group. `python -m marketplace.auth diagnose <user>` |

Never set `SSLVerification` to `NONE`. It will connect, and it will also hand
your session to whoever answered on that address.

#### If the CA cannot be installed on your machine

Then, and only then, fall back to a bearer token:

```bash
python -m marketplace.auth dbeaver alice.nakato        # form fields
python -m marketplace.auth dbeaver alice.nakato --url  # one JDBC URL
```

This hands over a token that expires and has to be reissued, so it does not
scale beyond a few people. Fix the trust store instead.

### Jupyter or a VS Code notebook

There is a working notebook at
[notebooks/marketplace_quickstart.ipynb](../notebooks/marketplace_quickstart.ipynb)
— open it and run the cells. The connection is:

```python
# pip install trino
import pandas as pd
from trino.dbapi import connect
from trino.auth import OAuth2Authentication

CA = r"C:/path/to/marketplace/generated/trino/tls/marketplace-ca.crt"   # the PEM, absolute

conn = connect(
    host="127.0.0.1", port=8443, catalog="iceberg", schema="marketplace",
    http_scheme="https", verify=CA,
    auth=OAuth2Authentication(),        # prints a sign-in URL the first time
    user="alice.nakato",                # your work account
)

cur = conn.cursor()
cur.execute("""
    SELECT process, workflow_stage, avg_waiting_days
    FROM marketplace.delay_analysis
    WHERE process = 'GMP' ORDER BY avg_waiting_days DESC LIMIT 10
""")
pd.DataFrame(cur.fetchall(), columns=[c[0] for c in cur.description])
```

If the cell seems to hang, `OAuth2Authentication` printed a sign-in URL into the
output — scroll up, open it, then re-run.

http://localhost:8501 — sign in with the same account. It shows only the

## Asking for a metric instead of writing SQL

Nineteen metrics are defined once, centrally, so everyone's "average waiting
days" is the same number.

This needs the dbt project, so it is an analyst and engineer tool rather than
something to run on a laptop with nothing installed:

```bash
cd marketplace/dbt
export PYTHONIOENCODING=utf-8        # Windows only; see SEMANTIC_LAYER.md
mf query --metrics delay_analysis_avg_waiting_days \
         --group-by delay_analysis__workflow_stage \
         --order -delay_analysis_avg_waiting_days
```

```
delay_analysis__workflow_stage      delay_analysis_avg_waiting_days
--------------------------------  ---------------------------------
GCP Inspection                                            12.3688
Safety & Efficacy Review                                  10.65
Technical Dossier Review                                   9.54444
```

Use this rather than hand-written SQL when you can. If the definition ever
changes, your number changes with it instead of quietly disagreeing.

## Your sandbox

You have a personal schema - `sandbox_<your_name>`, with dots replaced by
underscores, so `alice.nakato` gets `sandbox_alice_nakato`. You own it
completely, and nobody else can read it.

It is created for you when you are added to a group; you do not request one. If
it is missing, an administrator runs `python -m marketplace.identity provision`.

**Prefer views.** A view stores a definition, not data - about 600 bytes measured,
recomputed whenever you query it, and never stale.

```sql
CREATE OR REPLACE VIEW sandbox_alice_nakato.my_slow_stages AS
SELECT process, workflow_stage, avg_elapsed_days
FROM marketplace.delay_analysis
WHERE avg_elapsed_days > 20;
```

**Use a table only when you need a frozen copy** — a point-in-time snapshot for
a report, or something expensive you will query repeatedly:

```sql
CREATE TABLE sandbox_alice_nakato.q3_snapshot AS
SELECT * FROM marketplace.delay_analysis;
```

Tables are subject to a housekeeping policy: **untouched for 30 days and they
are dropped**, and each sandbox has a **5 GB quota**. Views are never dropped.
Nothing in your sandbox feeds a published report — to promote something, ask the
data team to add it as a product.

## Things that will not work, and why

| You try | What happens | Why |
|---|---|---|
| `SELECT * FROM nda_gold.fact_ma_applications` | Access denied | Physical tables are hidden; use the product instead |
| `SHOW SCHEMAS` shows only `marketplace` and your sandbox | Working as intended | You see what your group covers, plus your own workspace |
| Business user opens Quality Metrics | Access denied | Compliance findings identify named facilities |
| `INSERT INTO marketplace.…` | `Inserting into views is not supported` | Products are views over gold, not tables. Even an administrator cannot write to one |
| Writing to someone else's sandbox | Access denied | Sandboxes are private to their owner |
| Access disappears after a team move | Working as intended | You see what your new group sees; the change takes about a minute |
| `entity_id` looks like `sha256:4AC5…` | Working as intended | Applicant identifiers are masked for analysts; ask an administrator if you have a lawful need for the raw value |

## Getting help

- **A product is wrong or missing something** → its owner is on the
  OpenMetadata page.
- **You need access to a restricted product** → ask an administrator; access is
  by role, not by individual grant.
- **You need a new certified product** → the data team adds it to the
  declaration; it is a reviewed change, not a ticket to run some SQL.

Every query you run is logged with your username. That is normal for governed
data and is there to answer "who saw what", not to police your work.
